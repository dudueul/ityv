# 화면 명세

> English summary: Normative screen contents for every field device and app. Every screen carries a fixed bottom identity line (`{program} {semver} · 빌드 {build} · {first 16 Base32 characters of the fingerprint in four groups}`) that nothing may cover, next to a "소프트웨어 확인" action that opens the full component list with 32-character fingerprints. All on-screen and audio text comes from a fixed string table whose hash is in the release manifest; screens render only the state machine's current state and counts, never judgements, candidate names, read results, voter ordinals, pseudonyms or lists of imprint numbers. The document then fixes the contents of the scanner voter screen (visit-level), the scanner clerk/observer screen, the check-in clerk screen, the counting-centre ballot-sorter extension (an aid; the legal result stays the human-verified paper count), the station gateway screen, the observer app's attestation result and the voter verification app, and the accessibility rules (large type, high contrast, audio guidance, tactile buttons, never colour alone).

- 상태: 연구용 초안. 장치 인증의 시험 기준으로 쓴다.
- 관련: ADR-0021, ADR-0022, ADR-0023; `docs/spec/PROTOCOL.md` §5.8, §6.2, §7.1, §7.3, §7.9, §11.5; `docs/usecases/USE_CASES.md` 부록; `docs/ballot/BALLOT_LAYOUT.md` §14; VC-087.

## 0. 모든 화면에 공통

### 0.1 신원 줄
- 모든 화면의 **맨 아래 한 줄**은 신원 줄이다. 형식:
  `{프로그램 이름} {버전} · 빌드 {빌드} · {지문 앞 16자, 넷씩 넷}`
  예: `ityv 사전투표 스캐너 1.4.2 · 빌드 2071 · K7QF 2M8D R5WN Q3XA`
- 값은 부팅 때 잰 이미지에서 온다. 설정 파일이나 네트워크에서 오지 않는다. 여러 이미지로 된 장치는 릴리스 목록의 구성 이름·버전·빌드와 구성 해시의 지문을 쓴다(`ENCODING.md` §8.26).
- 대화상자, 경고, 화면 보호기, 전원 관리, 진행 표시 어느 것도 이 줄을 가리거나 흐리게 하지 않는다. 화면이 꺼질 때는 줄도 꺼지고, 켜지면 줄부터 그린다.
- 줄 오른쪽 끝에 늘 **소프트웨어 확인** 동작이 있다(화면 버튼이나 촉각 단추). 누르면 상세 화면이 열린다: 구성 요소마다 이름·버전·빌드·32자 지문(넷씩 여덟), 챔버 모듈마다 모듈 ID·빌드·지문, 부팅 횟수, "현장 증명을 하려면 참관인 토큰을 대거나 확인 카드를 넣으세요." 상세 화면은 투표 상태를 바꾸지 않으며, 유권자 화면에서 열면 10초 뒤 원래 화면으로 돌아간다.
- 이 줄과 상세 화면은 장치 자신의 주장이다. 증명은 현장 증명(PROTOCOL §7.9)이 한다. 화면 어디에도 "인증된 소프트웨어" 같은 판단 문구를 쓰지 않는다.

### 0.2 고정 문구 표
- 화면과 음성 안내의 모든 문구는 이미지에 들어 있는 **고정 문구 표**에서만 나온다. 표의 해시 `ui_strings_hash`는 릴리스 목록의 이미지 항목에 있다(`ENCODING.md` §8.26). 표가 바뀌면 새 릴리스다.
- 표의 항목은 문구 ID, 언어별 문자열, 들어갈 수 있는 값의 자리(정수, 투표함 ID 같은 식별자, 지문, 상태 어휘)뿐이다. 자유 문장, 외부에서 받은 문자열, 사람 이름은 넣을 수 없다.
- 화면은 상태기계의 **현재 상태와 수**만 그린다. 판단을 그리지 않는다. 금지 예: "정상", "부정 감지", "인증됨", "집계됨", "당신의 표가 반영되었습니다".
- 어느 화면에도 나오지 않는 것: 후보 이름이나 기호(유권자 화면), 판독 결과(BLANK·UNREADABLE 포함), 유권자의 순번("오늘 N번째"), 개별 사건의 시각, 가명, 투함 ID나 봉투 라벨의 목록, 각인 번호 목록.
- 상태 어휘(`UNVERIFIED`, `LOG_CONSISTENT`, `SOURCE_COMPLETENESS_CHECKED`, `CRYPTO_TALLY_VERIFIED`, `PAPER_AUDITED`, `HOLD_REVIEW`, `LEGAL_CERTIFIED`)는 PROTOCOL §14의 뜻으로만 쓰고 서로 바꿔 쓰지 않는다.

### 0.3 접근성
- 글자: 본문은 화면 높이의 4% 이상, 신원 줄은 2.5% 이상. 확대 단계 둘(1.5배, 2배). 확대해도 신원 줄은 맨 아래에 남는다.
- 대비: 본문 7:1 이상, 큰 글자와 신원 줄 4.5:1 이상. 고대비 모드는 흑백 반전.
- 색만으로 뜻을 전하지 않는다. 모든 상태는 글자와 모양(아이콘)을 함께 쓴다. 넣기와 확인 단추는 색뿐 아니라 모양(둥근 단추와 네모 단추)과 점자로 구별한다.
- 음성 안내: 유권자 화면의 모든 상태는 헤드폰 단자로 같은 문구 표의 음성으로 읽어 준다. 스피커로 내보내지 않는다(옆 사람이 듣지 않게).
- 촉각 단추: 넣기, 확인할 장 고르기, 위치 1–8 선택, 소프트웨어 확인, 다시 듣기. 화면을 만지지 않고 모든 동작을 할 수 있다.
- 언어: 한국어를 기본으로 하고, 문구 표에 등록된 언어만 고를 수 있다.

## 1. 투함 스캐너: 유권자 화면

방문 단위 투입(ADR-0021)을 따른다. 유권자 화면은 커밋먼트 유닛에 직접 연결되며 해석 유닛을 거치지 않는다(PROTOCOL §7.1).

| 상태 | 화면 문구 | 단추 |
|---|---|---|
| 대기 | "투표지를 봉투째 투입구에 넣어 주세요." | (없음) |
| 읽는 중 | "읽는 중이에요. 투표지 N장" | (없음) |
| 결정 | "투표지 N장을 읽고 잠갔어요." 아래에 위치 칸 1…N(장 번호만) | **모두 넣기** · **확인할 장 고르기** |
| 고르기 | "확인할 장을 고르세요. 확인한 장은 버리고 새로 찍어요." 위치 칸 1…N을 눌러 고름 | **고른 장 확인하기** · **돌아가기** |
| 확인 결과 | "고른 N장을 열어 인쇄했어요. 인쇄물을 보시고, 확인한 투표지는 새로 받아 찍어 주세요." | (없음) |
| 넣음 | "투표지 N장이 투표함에 들어갔어요. 전자 기록은 아직 공개 검증 전이에요(UNVERIFIED)." | (없음) |
| 쪽지 | "확인 번호 쪽지를 가져가세요. 이 번호로는 누구를 찍었는지 알 수 없어요." | (없음) |
| 겹침 | "투표지가 겹쳤어요. 돌려드린 투표지를 다시 넣어 주세요." | (없음) |
| 처리 못 함 | "이번 투표지는 처리하지 못했어요. 사무원을 불러 주세요." | (없음) |
| 비상 투입 | "지금은 스캐너를 쓸 수 없어요. 사무원 안내에 따라 비상 투입구를 써 주세요." | (없음) |
| 확인 카드 | "확인 카드를 읽었어요. 카드를 가져가세요." | (없음) |

- 결정 화면의 위치 칸에는 장 번호만 쓴다. 투표양식 이름, 후보, 판독 결과는 쓰지 않는다. 확인 결과(어느 후보로 읽었는지)는 화면이 아니라 검증 프린터의 인쇄물로만 나온다(PROTOCOL §8).
- 결정 화면은 모든 위치의 기록 서명이 끝난 뒤에만 단추를 켠다(VC-068). 그 전에는 "읽는 중"이다.
- 맨 아래 신원 줄: 구성 이름·버전·빌드·지문.

## 2. 투함 스캐너: 사무원·참관인 화면

| 항목 | 내용 |
|---|---|
| 투표함 | 투표함 ID, 상태(개시 전, 투표 중, 비상 투입 중, 마감 중, 마감됨) |
| 수 | 기록 수, 확인(검증 폐기) 수, 격리 수, 방문 수. 관외면 스티커 수 |
| 배치 | 지금 배치의 채움 `x/64`, 닫힌 배치 수 |
| 참관 서명 | 다음 `ScanCountAttest`까지 남은 기록 수(50건 기준)와 남은 시간(2시간 기준) |
| 저널 | 마지막 항목의 영속화 확인 여부, 오류가 있으면 오류 코드 |
| 송신 | 지금 슬롯 번호와 남은 시간, 이번 세션에 보낸 프레임 수(빈 프레임 포함), 밀린 닫힌 배치 수 |
| 챔버 모듈 | 챔버 코드마다 있음·없음·오류, 패드 잔량 비율 |
| 현장 증명 | 마지막 증명의 시간 구간과 참관인 ID, 개시 증명 여부 |

- 후보별 수, 판독 결과, 마지막 선택, 기록별 시각은 보이지 않는다(PROTOCOL §7.3 VC-062).
- 맨 아래 신원 줄. 상세 화면에서 구성 요소별 목록과 모듈 진술을 본다.

## 4. 개표소 투표지 분류기 확장

분류기는 지금 개표소에서 쓰는 종이 계수 장비에 각인 판독기와 신원 줄을 더한 것이다. 분류 결과는 보조 수단이며, 법적 결과는 사람이 심사·계수한 종이 결과다(PROTOCOL §11.4). 분류기는 연결 목록에 "연결 없음"으로 선언한다.

| 항목 | 내용 |
|---|---|
| 투표함 | 투표함 ID, 투표양식 |
| 종이 수 | 후보별로 분류된 종이 수, 미분류(사람 판정 대기) 수, 합계 |
| 등식 | `종이 수 = 기록 수 + 비상 투입 수`의 양변과 차이. 기록 수와 비상 투입 수는 마감 기록(공개 게시판 사본)에서 읽는다 |
| 각인 | 각인 없는 투표지 수(비상 투입분 제외), 같은 각인이 두 번 나온 수 |
| 상태 | 등식이 맞지 않거나 각인 이상이 있으면 "이 투표함은 HOLD_REVIEW로 기록됩니다" |

- 각인 번호 목록은 화면에도 출력물에도 내지 않는다. 수만 보인다(USE_CASES P).
- 후보별 종이 수는 분류 결과일 뿐이며 "확정"이나 "집계 완료"라고 쓰지 않는다.
- 맨 아래 신원 줄.

- 상태 어휘만 쓴다. 예: "이 추적코드는 체크포인트 N(LOG_CONSISTENT)에 포함되어 있어요. 누구를 찍었는지나 집계가 끝났는지를 뜻하지는 않아요."

## 8. 검사 방법

- 인증 시험에서 문구 표를 추출해 해시가 릴리스 목록과 같은지, 표에 금지 문구가 없는지, 값 자리가 허용된 종류뿐인지 확인한다.
- 화면 캡처 시험으로 모든 상태에서 신원 줄이 보이는지, 대화상자가 가리지 않는지, 확대·고대비에서도 남는지 확인한다.
- 음성·촉각만으로 방문 전체(넣기, 확인할 장 고르기)를 마칠 수 있는지 장애인 단체와 함께 시험한다.
